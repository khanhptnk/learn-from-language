# Designing pi^fb (the feedback reader) -- 2026-10-23

## What pi^fb must be

GFT defines pi^fb as pi conditioned on the feedback: pi^fb(tau | f) ∝ pi(tau) P_T(f | tau). For a Markov policy this
is, step by step (Bayes, exact):

    pi^fb(a | s, f) = pi(a | s) * P(f | s, a) / P(f | s)

where P(f | s, a) is the probability that the teacher says f if the agent takes a in s and then follows pi.
So pi^fb = **pi, reweighted by how much each action makes the feedback more likely**. Two facts follow:

1. **pi is known exactly.** Stage I episodes are generated by pi (or the frozen base when mixing); its action
   probabilities can be stored at collection time. Nothing about "acting like pi" needs to be learned.
2. **Only the reweighting depends on the feedback**, and it is a function of (state, action, feedback). For a feedback
   made of several statements that the teacher picks roughly independently, log P(f | s, a) ≈ sum over statements.

## Why the current readers fail (measured)

- They re-learn pi from scratch (loss 2.7 -> 0.54 = pi's own entropy); the feedback is a ~1% residual of the loss, so
  almost all gradient and capacity go to imitating pi. Even with feedback as clean tags (no language) the gain is only
  0.59 nats/episode.
- They read the whole feedback as one string. Whole strings are nearly unique, so with little data the network uses
  them as episode IDs (memorizes 100% of 256 episodes, chance on new ones), and with much data it ignores them.
- Statements are never learned on their own, so a new combination (the ideal feedback G*) means nothing to it.

## Design

**1. Residual on the known policy.** pi^fb logits = log pi_beh(a | s) (stored, no gradient) + Delta(s, a, f).
Delta = 0 gives exactly pi: an unfamiliar message falls back to pi, never to something worse, and all learning goes
into what the feedback changes. With base mixing, pi_beh is the base for base episodes.

**2. Statement-factored feedback.** Split f into sentences; encode each sentence separately (shared small text
encoder); Delta(s, a, f) = sum_j delta(s, a, sentence_j). Product of experts = the naive-Bayes form of log P(f | s, a).
Each sentence ("You still needed ore.") recurs across thousands of episodes, so it cannot act as an episode ID, and G*
is a sum of sentences whose parts were learned separately.

**3. Grounded per-sentence scorer.** delta(s, a, sentence) = <phi(s, sentence)_a, 1>: the sentence embedding queries
the map cells (cross-attention: "ore" -> ore cells), a planning pass propagates that relevance (the existing 8-pass
recurrent conv), and the agent's neighbourhood (attention-weighted crop, fixed version) plus inventory give one score
per action. Inventory enters next to the sentence because whether "you still needed ore" applies depends on what is
already held.

**4. Dense auxiliary signal from the same Stage I data** (no extra data): from every state, predict which sentences
occur in the episode's feedback (contrastive: true sentences vs sentences of other episodes in the batch; label =
mentioned or not). Every step supervises every sentence, instead of the ~1% of steps whose action depends on it.
This teaches what each sentence means in terms of states (what "got metal" looks like), which Delta then uses.
Loss = Stage I MLE (unchanged objective) + lambda * auxiliary.

## How this matches the algorithm

- Same Stage I data, same MLE objective for pi^fb; the auxiliary loss only shapes the representation.
- pi^fb stays "pi prompted with feedback" in the paper's sense: its distribution is pi times a learned likelihood ratio,
  which is exactly the posterior the paper defines; Stage II and damping unchanged.
- Fairness: the deployed pi is untouched (same network for all methods); only GFT's training-only reader changes
  (the paper's fairness rule already allows a different pi^fb).

## Validation before any GFT run (cheap, offline, pixels)

On the existing 16k-episode benchmark (pi's episodes, held-out tasks), against the current reader:
1. Specific gain and retrieval on new episodes, text input. Target: retrieval well above chance (>= 0.6).
2. Data efficiency at GFT's scale (256 episodes per round, replay): the gain must appear with that much data.
3. Steering: roll out pi^fb with G* vs the request alone; success must go up.
4. Ablations (one each): no residual (current reader), whole-string feedback (no factoring), no auxiliary loss.
CPU unit tests and a local smoke first; GPU only for the final table (~1 h).

## Known limits

- A sentence about an outcome pi has never reached ("you did get some metal" at the frontier) still has no data;
  base mixing (ADEL) supplies such episodes. The residual design makes the fallback pi, not noise.
- Factoring assumes statements are roughly independent given the trajectory; the teacher's statements are, mostly.
